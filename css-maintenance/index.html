Сопровождение CSS

Единый файл assets/css/styles.css обеспечивает весь сайт. Перед рефакторингом нужно понимать группы стилей, риски и контрольные страницы, чтобы не изменить внешний вид случайно.

Текущий вывод

Файл CSS компактный и загружается одним запросом, но почти не разделён на логические секции. Это повышает риск случайных изменений: один класс может использоваться на главной, карточках ТОС, новостях и служебных страницах одновременно.

Безопасная стратегия: сначала вести карту групп и контрольных страниц, затем добавлять комментарии или исходные модульные CSS-файлы, а итоговый styles.css оставлять совместимым для сайта.

Что нельзя делать резко

  • переименовывать существующие классы;
  • менять сетку карточек без проверки мобильной версии;
  • удалять якобы неиспользуемые классы без поиска по страницам и JS;
  • менять CSS-переменные без просмотра светлой и тёмной темы.

Контрольные страницы

  • главная страница;
  • каталог ТОС и карточка ТОС;
  • раздел новостей и отдельная новость;
  • табличные рабочие страницы;
  • мобильное меню на 360–620px;
  • печать чек-листов.

Первый безопасный шаг

Не менять визуальные значения, а добавить карту разделов и порядок проверки. После этого можно разделять исходники на компоненты и собирать итоговый styles.css.

Открыть инвентарь

Рекомендуемый порядок рефакторинга

  1. Зафиксировать текущие контрольные страницы и размеры экрана.
  2. Добавить комментарии-разделители в CSS без изменения правил.
  3. Отделить токены, базу, кнопки, карточки, таблицы, главную, адаптивность и печать.
  4. Проверить отсутствие изменений в `data/site_health.json`, внутренних ссылках и SEO.
  5. После визуальной проверки обновить этот CSV и статус проекта.
