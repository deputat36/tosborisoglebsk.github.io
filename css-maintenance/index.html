Сопровождение CSS

Единый файл assets/css/styles.css обеспечивает весь сайт. Перед рефакторингом нужно понимать группы стилей, риски и контрольные страницы, чтобы не изменить внешний вид случайно.

Текущее состояние: визуальные значения CSS не меняются. Сначала фиксируется контрольный baseline, затем выполняются только проверяемые структурные изменения.

Текущий вывод

Файл CSS компактный и загружается одним запросом, но почти не разделён на логические секции. Это повышает риск случайных изменений: один класс может использоваться на главной, карточках ТОС, новостях и служебных страницах одновременно.

Безопасная стратегия: сначала зафиксировать 14 контрольных случаев на существующих маршрутах и размерах экрана, затем добавлять комментарии или исходные модульные CSS-файлы. Итоговый styles.css должен оставаться совместимым с текущими страницами.

Что нельзя делать резко

  • переименовывать существующие классы;
  • менять сетку карточек без проверки мобильной версии;
  • удалять якобы неиспользуемые классы без поиска по страницам и JavaScript;
  • менять CSS-переменные без просмотра светлой и тёмной темы;
  • отмечать проверку как пройденную без ссылки на доказательство.

Контрольный набор

  • главная страница;
  • каталог и карточка ТОС;
  • раздел новостей и отдельная новость;
  • рабочая панель и табличная страница;
  • ширины 360, 620, 900 и 1180px;
  • светлая и тёмная тема;
  • мобильное меню;
  • предпросмотр печати чек-листа.

Первый безопасный шаг

Открыть каждый случай из CSV, сохранить исходный снимок и заполнить evidence_ref. Только после этого добавлять комментарии-разделители в styles.css.

Статусы контрольных случаев

Статус описывает не намерение, а фактически выполненный этап проверки

baseline_required

Нужен исходный снимок

Случай описан, но внешний вид ещё не зафиксирован.

baseline_captured

Baseline сохранён

Есть ссылка на исходный снимок или иной результат проверки.

passed

Сравнение пройдено

После CSS-изменения контрольный случай сравнили с baseline, отличий нет.

failed / blocked

Нужна работа

Обнаружено отличие либо проверка временно невозможна. Причина фиксируется в notes.

Рекомендуемый порядок рефакторинга

  1. Зафиксировать исходные снимки для всех случаев со статусом baseline_required.
  2. Указать доказательства в evidence_ref и статус baseline_captured.
  3. Добавить комментарии-разделители в CSS без изменения правил и значений.
  4. Повторить те же контрольные случаи.
  5. При отсутствии отличий поставить passed.
  6. Проверить нулевой accessibility baseline, внутренние ссылки, SEO и бюджеты ресурсов.
  7. После фактической проверки обновить инвентарь и issue #165.
