# Логотипы ТОС

Сюда загружаются реальные логотипы отдельных ТОСов.

## Как называть файлы

Файл должен называться так же, как `slug` ТОС в `data/toses.json`.

Примеры:

```text
bogana.png
vostochnyy.png
gubari.svg
mahrovka.jpg
uyutnyy.png
chkalovec.svg
```

## Поддерживаемые форматы

- SVG — лучший вариант для сайта: лёгкий, чёткий, хорошо масштабируется.
- PNG — если логотип только картинкой.
- JPG/JPEG — если другого исходника нет.
- WEBP — если нужно уменьшить вес.

Рекомендуемые размеры для PNG/WEBP: 512×512 px или 800×800 px.

## Как логотип подключается к карточке

Скрипт `scripts/sync_tos_logos.js` автоматически проверяет эту папку и прописывает найденный файл в поле `logo` нужной карточки ТОС.

Например, если есть файл:

```text
assets/img/tos-logos/bogana.png
```

то в `data/toses.json` будет указано:

```json
"logo": "/assets/img/tos-logos/bogana.png"
```

Если у одного ТОС лежит несколько файлов с разными расширениями, приоритет такой:

```text
svg → png → jpg → jpeg → webp
```

Если логотипа нет, сайт покажет аккуратный круглый знак с инициалами ТОС.

## Передача логотипов редакции через ChatGPT

1. Владелец сайта присылает изображение и название ТОС (или указывает ТОС в сообщении). Можно передавать JPG, PNG, WEBP или SVG.
2. Сверить название со `slug` в `data/toses.json`; не создавать новый ТОС, если карточка уже есть.
3. Подготовить квадратную версию без искажения фирменного знака, с полями, сохранив исходные цвета, надписи и пропорции. Для сайта предпочтителен оптимизированный WEBP; SVG использовать только из достоверного векторного исходника.
4. Сохранить `assets/img/tos-logos/<slug>.<ext>`. Перед заменой проверить одноимённые файлы другого расширения: скрипт имеет приоритет SVG → PNG → JPG → JPEG → WEBP. Не оставлять устаревшие версии с более высоким приоритетом.
5. Установить в поле `logo` канонического JSON путь к реальному файлу. Обновить `updated_at` как дату технической правки, без повышения статуса проверки других сведений.
6. Обновить статус проекта, запустить генератор `scripts/sync_tos_logos.js` и проверку сборки, убедиться, что карточка, каталог, SEO-метаданные, проверка полноты и опубликованный файл корректны. Не считать отправку в GitHub фактом публикации до проверки публичного URL.

Действующая автоматизация уже связывает логотип с карточкой. Дополнительный интерфейс загрузки для председателей не требуется.
