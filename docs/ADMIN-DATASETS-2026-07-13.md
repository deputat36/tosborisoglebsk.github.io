# Коллекции локальной админ-панели

Дата: 13 июля 2026 года.

## Назначение

Админ-панель редактирует девять публичных JSON-коллекций без прямой записи в GitHub:

1. `data/toses.json` — каталог ТОС;
2. `data/news.json` — новости;
3. `data/articles.json` — материалы;
4. `data/documents.json` — документы;
5. `data/grants.json` — конкурсы и гранты;
6. `data/projects.json` — проекты и идеи;
7. `data/done.json` — результаты проектов;
8. `data/events.json` — календарь;
9. `data/needs.json` — потребности.

Восемь базовых схем находятся в `admin/admin2.js`. Схема результатов и её вкладка устанавливаются `admin/admin-dashboard.js`, который уже входит в разрешённый набор модулей.

## Результаты проектов

Раздел «Результаты» работает с `data/done.json`.

Поля:

- `id` — уникальный идентификатор;
- `status` — `draft` или `published`;
- `date` — дата материала;
- `tos_slug` — связь с карточкой ТОС;
- `type` — тип результата;
- `title` — заголовок;
- `summary` — краткое описание;
- `before` — состояние до работ;
- `done` — выполненные работы;
- `result` — итог для территории;
- `participants` — участники;
- `source_label` — название источника;
- `source_url` — проверяемая ссылка;
- `needs_details` — недостающие подтверждения;
- `content_origin` — происхождение материала.

Новая запись создаётся как `draft` с `content_origin=editorial`. Это предотвращает автоматическую публикацию неподтверждённого результата.

Допустимые значения `content_origin`:

- `verified`;
- `editorial`;
- `starter`;
- `request`.

Перевод в `verified` не выполняется автоматически и требует проверяемого источника.

## Dashboard

Dashboard учитывает `done.json` и показывает:

- количество опубликованных результатов;
- количество результатов, ожидающих подтверждений;
- результаты с неизвестным `tos_slug`;
- редакционные и неподтверждённые результаты;
- число результатов, привязанных к ТОСам.

Запись считается ожидающей подтверждений, если она не имеет `content_origin=verified`, не содержит `source_url` или содержит непустое `needs_details`.

## Связи

Для новостей, проектов, результатов, событий и потребностей непустой `tos_slug` должен существовать в `data/toses.json`.

Пустой `tos_slug` допускается для материалов общего характера, но dashboard показывает отсутствие привязки там, где это важно для рабочего процесса.

## Schema-аудит

`scripts/audit_admin_dataset_schema.js` проверяет:

- наличие девяти JSON-файлов;
- что каждая коллекция является массивом объектов;
- ключевые идентификаторы и отсутствие дублей;
- наличие полей названия;
- корректность непустых связей `tos_slug`;
- наличие схемы каждого файла в админке;
- наличие вкладки и справки для `done.json`;
- полный набор полей результата;
- контролируемый список `content_origin`;
- загрузку всех девяти коллекций dashboard-модулем;
- сохранение архитектуры из пяти script-src.

Проверка выполняется read-only workflow `Audit admin dataset schemas`.

## Границы

Пакет не меняет содержимое JSON-файлов и не повышает статусы доверия. Он только делает существующую коллекцию `done.json` доступной в локальном редакторе и защищает согласованность схем.
