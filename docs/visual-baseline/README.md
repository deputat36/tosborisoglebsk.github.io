# Доказательства визуальной регрессии

Каталог предназначен для разрешённых к публикации снимков контрольных страниц портала ТОС БГО.

Основная матрица: `data/css_regression_matrix.csv`.
Правила сопровождения: `docs/CSS-MAINTENANCE.md`.
Структурные пользовательские сценарии: `data/user_journey_matrix.csv`.

## Что считается доказательством

Поле `evidence_ref` может содержать:

- путь к существующему файлу в публичном репозитории, например `docs/visual-baseline/css-reg-001-home-1180x900-light.png`;
- ссылку `https://...` на вложение GitHub issue или pull request;
- ссылку на иной устойчивый источник, доступный проверяющему без закрытых учётных данных.

Локальный путь обязан существовать. Произвольный текст, имя файла без пути и ссылка на закрытый личный диск доказательством не считаются.

## Имена файлов

Рекомендуемый шаблон:

`<case_id>-<area>-<width>x<height>-<theme>-<state>.png`

Примеры:

- `css-reg-001-home-1180x900-light-baseline.png`;
- `css-reg-003-home-360x800-light-menu-open.png`;
- `css-reg-007-tos-card-360x800-dark.png`;
- `css-reg-014-field-checklist-print.png`.

Используйте латиницу, цифры и дефисы. Не включайте в имя ФИО, телефон, адрес, email или другие персональные данные.

## Минимальный состав доказательства

На снимке должны быть видны:

- проверяемая область страницы;
- состояние темы;
- открытое меню или другое действие, если оно указано в матрице;
- отсутствие горизонтальной прокрутки, наложений и обрезания ключевых элементов;
- для печати — результат предпросмотра, а не только экранная версия.

## Безопасность

Перед публикацией снимка проверьте:

- нет ли закрытых персональных данных;
- нет ли черновых обращений, переписки и служебных токенов;
- разрешено ли публиковать показанные фотографии и логотипы;
- не отображаются ли данные из локального хранилища браузера;
- не попали ли в кадр вкладки, уведомления или данные других систем.

При сомнении используйте отдельный чистый профиль браузера и публичную версию сайта.

## Статусы матрицы

- `baseline_required` — доказательства ещё нет; `evidence_ref` должен быть пустым;
- `baseline_captured` — исходный снимок сохранён и ссылка существует;
- `passed` — после изменения выполнено сравнение с baseline;
- `failed` — найдено отличие, в `notes` описана проблема;
- `blocked` — проверка невозможна, в `notes` указана конкретная причина.

Статус `passed` нельзя использовать как замену `baseline_captured`: он означает повторную проверку после изменения.

## Порядок фиксации

1. Открыть маршрут из `data/css_regression_matrix.csv`.
2. Установить точный viewport, тему, режим и действие.
3. Проверить `expected_check`.
4. Сохранить разрешённый снимок или GitHub-вложение.
5. Записать устойчивую ссылку в `evidence_ref`.
6. Изменить статус на `baseline_captured`.
7. Запустить `npm run audit:css-regression`.

После CSS-изменения повторить тот же кейс, сравнить результат и установить `passed` либо `failed`.
