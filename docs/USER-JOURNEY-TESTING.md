# Проверка пользовательских маршрутов портала ТОС БГО

Дата актуализации: 14 июля 2026 года.

## Назначение

Документ фиксирует минимальные пользовательские сценарии, которые должны оставаться рабочими при изменениях навигации, генераторов, шаблонов и JavaScript.

- источник сценариев: `data/user_journey_matrix.csv`;
- автоматическая проверка: `scripts/audit_user_journey_matrix.js`;
- визуальная матрица: `data/css_regression_matrix.csv`.

Структурный аудит отвечает на вопрос, существуют ли маршруты и наблюдаемые элементы сценария. Он не выдаёт наличие HTML-блока за подтверждение актуальности сведений или удобства интерфейса.

## Что проверяется автоматически

- матрица содержит ровно пять обязательных сценариев и корректные заголовки;
- идентификаторы, сочетания маршрутов и взаимодействия не дублируются;
- заполнены аудитория, цель, маршруты, токены, viewport, evidence и примечание;
- стартовая и конечная страницы существуют и не закрыты `noindex`;
- на стартовой странице присутствует нужная ссылка или управляющий элемент;
- конечная страница содержит обязательные элементы сценария;
- карточка ТОС ведёт в конструктор исправления с выбранным ТОС и типом `card`;
- конструктор обновления содержит выбор сценария, форму и кнопку копирования;
- маршрут председателя ведёт к комплекту проекта и паспорту проекта;
- мобильное меню имеет `aria-expanded`, закрывается по Escape и клику вне меню, блокирует прокрутку и закрывается после перехода;
- полный публичный навигатор остаётся доступным через `/sections/`;
- аудит подключён к `package.json`, обычному и полному project-mode.

## Что автоматический аудит не доказывает

- что опубликованные контакты, председатели и границы актуальны;
- что форма фактически отправляет сообщение редакции;
- что страницы визуально корректны во всех браузерах;
- что элементы удобно нажимать пальцем;
- что поиск даёт подходящий результат для любого реального адреса;
- что печать помещается на конкретную модель принтера;
- что юридические инструкции применимы без актуальной официальной сверки.

## Основные сценарии

### 1. Житель находит свой ТОС

Маршрут: `/` → `/tos/` → карточка ТОС.

Ожидаемый результат:

- каталог доступен с главной;
- поиск работает по опубликованным сведениям;
- список имеет статический резерв для браузеров без JavaScript;
- пользователь видит предупреждение, что каталог является рабочей версией.

### 2. Житель открывает карточку

Маршрут: `/tos/` → `/tos/mirolyubie/`.

Ожидаемый результат:

- в каталоге есть ссылка на карточку;
- карточка показывает блок председателя и контактов;
- статус проверки не смешивается с технической датой редактирования;
- при отсутствии или сомнительности сведений есть путь отправки уточнения.

Карточка `mirolyubie` используется только как стабильный технический fixture. Аудит не подтверждает опубликованные в ней сведения.

### 3. Пользователь сообщает об ошибке

Маршрут: карточка ТОС → `/update-tos/?tos=mirolyubie&type=card#message-builder`.

Ожидаемый результат:

- выбран сценарий обновления карточки;
- пользователь заполняет только нужные поля;
- результат формируется как готовое сообщение;
- отправка не выполняется автоматически от имени пользователя.

### 4. Председатель готовит проект

Маршрут: `/chairperson/` → `/chairperson/project/`.

Ожидаемый результат:

- доступен выбор маршрута: своими силами, с партнёром, через конкурс или поэтапно;
- доступны комплект документов и паспорт проекта;
- маршрут заканчивается фотоотчётом и итоговым отчётом;
- конкурсные и юридические требования обозначены как требующие отдельной сверки.

### 5. Пользователь открывает мобильное меню

Маршрут: главная страница → мобильное меню → `/sections/`.

Ожидаемый результат:

- кнопка меню изменяет `aria-expanded`;
- открытое меню блокирует прокрутку страницы;
- Escape и клик вне меню закрывают его;
- после перехода меню закрывается;
- `/sections/` показывает основные публичные маршруты без смешивания с редакционными инструментами.

## Визуальная проверка

Автоматический структурный smoke не заменяет визуальный baseline. Визуальные и responsive-регрессии контролируются через `data/css_regression_matrix.csv`.

Особое внимание требуется для:

- главной страницы в светлой и тёмной теме;
- мобильного меню на ширинах 360 и 620 пикселей;
- каталога и карточки ТОС;
- рабочей и табличной страницы;
- печатной версии чек-листа.

## Команды

- `npm run audit:user-journeys`;
- `npm run audit:css-regression`;
- `npm run audit:project-mode-full`.

## Правило изменений

Новый пользовательский маршрут добавляется только тогда, когда он решает отдельную задачу аудитории. Для него нужно:

1. добавить строку в `data/user_journey_matrix.csv`;
2. указать стартовую и конечную страницы;
3. определить наблюдаемые структурные признаки;
4. добавить визуальный case, если меняется интерфейс;
5. не считать структурный smoke доказательством актуальности данных, фактической отправки или юридической применимости.
