# Принятые решения

## Рабочая ветка

Основная рабочая ветка проекта — `release-2025-12-22`. Ветка `main` не считается основной без отдельного решения владельца.

## Связь данных

Новости, проекты, потребности, события и результаты привязываются к ТОС через `tos_slug`. Дублирование карточек одного ТОС не допускается.

## Проверка данных

Заполненность карточки не означает полную проверку. Для подтверждения используются `verification_status`, `verified_at`, `verification_source` и `verification_note`. Устаревшие проверки отмечаются отдельно.

Если у карточки нет явного `verification_status`, публичная карточка не должна называть сведения подтверждёнными. В этом случае статус выводится как «проверено частично», «требует проверки», «данные уточняются» или «проверка устарела» на основе заполненности и даты обновления.

## Передача материалов

Раздел `/update-tos/` работает без серверного хранения. Форма формирует текст на устройстве пользователя, сохраняет черновик только в браузере и передаёт материал на ручную проверку редакции.

Определения полей находятся в `assets/js/update-center-data.js`, логика конструктора — в `assets/js/update-center.js`.

Ссылки на конкретный сценарий передачи материалов должны использовать формат `/update-tos/?tos=<slug>&type=<scenario>#message-builder`, где `<scenario>` — `card`, `news`, `photo`, `event`, `project` или `need`. Старые ссылки на несуществующие якоря вида `/update-tos/#template-project` не использовать.

## Технический аудит

Отчёт состояния сайта должен проверять не только существование внутренних страниц и файлов, но и существование указанных якорей `#id` / `#name` на целевых страницах.

После каждого обновления `data/site_health.json` в полном локальном аудите должна заново генерироваться `/actions-check/`. Проверка project-mode запускается только после этой синхронизации.

Accessibility/performance-бюджеты измеряют только публичные runtime-ресурсы из `assets/`, `admin/`, `data/` и корня сайта. Служебные Node.js-скрипты, workflow-файлы и документационные visual baseline PNG не считаются браузерной нагрузкой.

Утверждённые 14 visual baseline-сценариев основной ветки являются обязательной защитой CSS. Содержательное изменение stylesheet требует нового канонического fingerprint и успешного pixel comparison; закрытый без слияния PR #220 не может использоваться как актуальное visual evidence.

## Конфиденциальность

Форма запрашивает только сведения, необходимые редакции. Контакт для уточнения не публикуется автоматически.

Пока оператор портала, цели обработки, формы согласий и закрытое хранилище не утверждены, `/privacy/` используется только как редакционная памятка. Сбор подписанных согласий, автоматическая публикация обращений и хранение оригиналов доказательств в публичном репозитории запрещены.

Публичные отчёты об основаниях публикации должны быть обезличенными: допускаются slug, типы полей, количества и флаги готовности, но не ФИО, телефоны, email и исходные URL. Статус отчёта не считается юридической оценкой или согласием.

Очередь внешней проверки может фиксировать только приоритет, slug, типы полей, reason codes и следующий шаг. До реальной отправки и подтверждения все задачи остаются `pending_external_confirmation`; статусы `sent`, `waiting` и `received` автоматически не выставляются.

Шаблоны фактического подтверждения являются только редакционными запросами. Ответ может стать обезличенным источником уточнения факта после проверки, но не создаёт `publication_consent_ref`, не повышает статус доверия карточки и не разрешает публикацию нового личного контакта. В публичном репозитории фиксируются только поля из закрытого allowlist; свободный текст, адресаты, контакты, сырая переписка и закрытые ссылки запрещены.
