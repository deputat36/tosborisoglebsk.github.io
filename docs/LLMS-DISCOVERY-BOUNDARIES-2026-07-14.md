# Границы публичного и редакционного контента в llms.txt

Дата фиксации: 14 июля 2026 года.

## Цель

`llms.txt` используется как краткая карта сайта для AI-систем и автоматических агентов. Он не должен рекомендовать внутренние редакционные страницы как самостоятельные публичные источники.

## Зависимость от PR №246

Пакет основан на PR №246, который переводит в `noindex,follow`:

- `/data-requests/priority-tos/`;
- `/data-requests/tos-registry-request/`.

Общий `/data-requests/` также относится к рабочему редакционному маршруту. Эти страницы остаются доступны по прямым ссылкам, но не должны входить в публичные рекомендации, sitemap или основные методические разделы `llms.txt`.

## Новая структура llms.txt

Публичными считаются только разделы:

- `Основные публичные разделы`;
- `Публичные методические разделы`;
- `Открытые данные`.

Рабочие маршруты перечисляются отдельно в разделе `Рабочие страницы` с явным предупреждением, что они:

- предназначены для редактора;
- закрыты от индексации через `noindex`;
- не являются основными публичными разделами;
- не должны рекомендоваться как самостоятельные источники.

## Защита генератора

`scripts/patch_llms_links.js`:

- больше не добавляет `/data-requests/` в публичный список;
- удаляет абсолютные URL трёх редакционных маршрутов;
- восстанавливает единый рабочий notice;
- сохраняет публичные методические ссылки и открытые данные.

Это важно, потому что основной workflow запускает patch-скрипт повторно и без исправления мог бы вернуть устаревшую рекомендацию.

## Блокирующий аудит

`scripts/audit_llms_discovery_boundaries.js` проверяет:

1. существование публичных разделов;
2. отсутствие дублирующихся публичных рекомендаций;
3. существование каждого публично рекомендованного HTML-маршрута;
4. отсутствие `noindex` у публично рекомендованных страниц;
5. наличие трёх редакционных маршрутов только в рабочем разделе;
6. `noindex` у соответствующих HTML-страниц;
7. отсутствие этих URL в sitemap;
8. защиту `patch_llms_links.js`;
9. подключение к package, project-mode и read-only workflow.

## Read-only workflow

`.github/workflows/llms-discovery-audit.yml` применяется для stacked PR и имеет только право `contents: read`.

Последовательность:

1. проверка синтаксиса JavaScript;
2. запуск `patch_llms_links.js`;
3. регенерация sitemap;
4. аудит редакционных страниц из PR №246;
5. аудит границ `llms.txt`;
6. полный project-mode.

Workflow не коммитит изменённый `llms.txt`, sitemap или другие generated-файлы.

## Границы

- тексты запросов и данные ТОСов не изменяются;
- редакционные страницы не удаляются;
- `noindex,follow` сохраняет внутреннюю навигацию;
- публичная форма `/update-tos/` остаётся рекомендуемым маршрутом для передачи материалов;
- успешный PR-CI не заменяет post-merge проверку основной ветки и Pages deployment.
