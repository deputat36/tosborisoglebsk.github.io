## Актуальный редакционный маршрут

1. Проверить `/source-watch/` и зафиксировать находку в `/content-discovery/`.
2. Использовать первичный документ для результата, не подменяя им подтверждение реализации.
3. В `/outreach-register/` закрывать найденным источником только задачи со статусом `resolved` и ссылкой на документ.
4. По «Миролюбию» запросить сроки, текущий статус и разрешённые материалы.
5. По остальным четырём ТОС запросить подтверждение итога и дальнейшие планы.
6. Полученные ответы провести через `/reply-review/` и профильную матрицу.
7. Передать проверенный материал в `/content-intake/` и `/publication-queue/`.
8. При статусе `ready` обновить целевой JSON или страницу.
9. Пройти `/post-publish-check/` и `/freshness-check/`.
10. Раз в квартал заполнить `/quarterly-report/`.
11. После крупных изменений открывать `/actions-check/` и обновлять CSV диагностики.
12. Перед изменениями CSS открывать `/css-maintenance/` и проверять контрольные страницы.
13. Ручные действия вести через GitHub-задачи #34, #164, #165 и #166.
14. Для сводки ручных блоков использовать `/github-tasks/`.
