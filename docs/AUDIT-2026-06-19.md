# Аудит портала ТОС БГО от 19 июня 2026 года

## Цель

Провести свежий аудит сайта после доработок 18–19 июня и определить, что можно улучшать без дополнительного согласования: технические проверки, рабочие страницы, навигацию, понятность сценариев, документацию и безопасные пометки о статусе данных.

Рабочая ветка проекта: `release-2025-12-22`.

## Краткий вывод

Портал уже готов к публичному запуску как информационная площадка и рабочий инструмент для сбора сведений. Главный риск сейчас не в отсутствии страниц, а в трёх вещах:

1. Сгенерированные HTML-карточки ТОС ещё могут отставать от улучшенного шаблона.
2. Полный технический отчёт `/data/site_health.json` отсутствует до успешной генерации.
3. Данные большинства карточек пока не подтверждены председателями или открытыми источниками.

## Что уже сильное

- Есть каталог ТОС и отдельные карточки.
- Есть связанные разделы: новости, проекты, потребности, события, результаты.
- Есть центр передачи материалов `/update-tos/` с сценариями.
- Есть рабочие страницы: `/audit/`, `/data-quality/`, `/data-requests/`, `/site-health/`, `/communication-kit/`.
- Есть GitHub Actions и генераторы страниц.
- Есть документация проекта и статус текущих работ.
- Есть runtime-защита старых карточек через `assets/js/site.js`.

## Главные проблемы на 19 июня 2026 года

### 1. Сгенерированные HTML-карточки не подтверждены как обновлённые

Повторная проверка показала, что `/tos/ivanovka/` в репозитории всё ещё содержит старые ссылки вида:

- `/update-tos/?tos=ivanovka`;
- `/update-tos/#template-project`;
- `/update-tos/#template-need`;
- `/update-tos/#template-photo`.

Это не ломает пользовательский путь полностью, потому что работает runtime-защита, но статический HTML нужно пересобрать.

### 2. Полный отчёт здоровья сайта пока не найден в `data/`

Страница `/site-health/` загружает `/data/site_health.json`. Если файл не создан генератором, страница должна показывать понятный fallback, а не только сообщение об отсутствии отчёта.

### 3. Рабочие страницы не должны конкурировать с публичными страницами в поиске

Страница `/site-health/` является рабочей страницей контроля качества. Её можно открывать по ссылке, но не нужно продвигать в поисковой выдаче как публичный материал для жителей.

### 4. Доверие к карточкам важнее объёма контента

По аудиту от 18 июня: 24 карточки ТОС, 4 высокого приоритета, 0 подтверждённых карточек, 4 без телефона, 4 без соцсетей. Значит главный следующий результат — не новые декоративные блоки, а подтверждение первых карточек.

## Что можно улучшать самостоятельно

Можно делать без дополнительного участия владельца проекта:

1. Исправлять битые внутренние ссылки и якоря.
2. Добавлять fallback-состояния для рабочих страниц.
3. Улучшать безопасный вывод данных в JS через HTML-экранирование.
4. Добавлять `noindex` на рабочие технические страницы.
5. Улучшать инструкции, памятки, чек-листы и статус проекта.
6. Добавлять ссылки на уже существующие формы и сценарии.
7. Улучшать навигацию между рабочими страницами.
8. Создавать GitHub issues для задач, где требуется ручная проверка.
9. Добавлять пометки «требует уточнения», если данные неполные.
10. Улучшать тексты без добавления новых фактов, телефонов, имён, дат и адресов.

## Что нельзя делать без подтверждения

Нельзя самостоятельно:

1. Менять председателей, телефоны, email, границы, численность ТОС.
2. Переводить карточку в `verified`, если нет подтверждения.
3. Добавлять факты о проектах, суммах, победах, партнёрах и датах без источника.
4. Публиковать закрытые персональные данные.
5. Удалять runtime-защиту, пока статические карточки не пересобраны и не проверены.

## Автономный план работ

### Этап 1. Работоспособность рабочих страниц

Статус: начато.

- Добавить fallback на `/site-health/`, если `/data/site_health.json` отсутствует.
- Показывать сводку по `data/tos_content_audit.json`, пока нет полного технического отчёта.
- Добавить прямые кнопки к карточке и сценарию уточнения.
- Экранировать значения, которые выводятся из JSON в HTML.
- Добавить `noindex,nofollow` на `/site-health/`.

### Этап 2. Генерация и старые HTML-карточки

Статус: вынесено в задачу #41.

- Вручную запустить `Generate TOS pages`.
- Проверить новый автокоммит `Generate SEO pages, sitemap and audit`.
- Проверить HTML-карточки Ивановки, Подстёпок, Губарей и Танцырея.
- После успешной пересборки удалить временный `data/regeneration_request.json`.

### Этап 3. Доверие к данным

Статус: вынесено в задачу #34.

- Отправить запросы по 4 карточкам высокого приоритета.
- Получить подтверждение открытых данных.
- После получения сведений обновить `data/toses.json`.
- Только после подтверждения переводить карточки в `verified`.

### Этап 4. Контент и запуск

- Использовать `/communication-kit/` для закреплённого поста.
- Использовать отдельный пост по 4 ТОСам для сбора сведений.
- После получения данных добавить реальные новости, фотоотчёты, проекты и потребности.

### Этап 5. Техническая устойчивость

- Проверить, что workflow стабильно формирует `data/site_health.json`.
- Добавить отдельный smoke-чек ключевых страниц, если текущего аудита будет недостаточно.
- Следить, чтобы рабочие страницы не попадали в поисковую выдачу без необходимости.
