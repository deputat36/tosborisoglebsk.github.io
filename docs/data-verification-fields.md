# Поля проверки данных карточки ТОС

В `data/toses.json` каждая карточка должна содержать отдельный объект `trust`.

```json
{
  "trust": {
    "source_type": "",
    "source_ref": "",
    "checked_at": "",
    "checked_by": "",
    "recheck_after": "",
    "verification_scope": [],
    "publication_consent_ref": ""
  }
}
```

Пустые значения означают, что доказательная проверка ещё не зафиксирована. Они не дают карточке статус `verified` или `partial`.

## Значение полей

- `source_type` — тип источника: официальный документ, председатель ТОС, уполномоченный представитель, официальный ответ.
- `source_ref` — обезличенный идентификатор или ссылка на источник. Закрытые документы и переписку нельзя хранить в публичном GitHub.
- `checked_at` — дата фактической проверки сведений в формате `YYYY-MM-DD`.
- `checked_by` — роль или идентификатор проверившего без лишних персональных данных.
- `recheck_after` — дата следующей плановой сверки.
- `verification_scope` — перечень реально проверенных полей, например `chairperson`, `phones`, `boundaries`.
- `publication_consent_ref` — обезличенная ссылка на основание публикации персональных контактов или медиа.

## Допустимые статусы карточки

- `verified` — данные проверены полностью по установленной матрице.
- `partial` — подтверждена только часть сведений.
- `needs_review` — карточку нужно проверить или перепроверить.
- `stale` — срок повторной проверки истёк.
- `unknown` — применяется только для записей, состояние которых невозможно классифицировать.

## Главные правила

1. `updated_at` отражает изменение записи или файла на сайте. Это не доказательство актуальности сведений.
2. `checked_at` можно заполнять только вместе с `source_type`, `source_ref`, `checked_by` и непустым `verification_scope`.
3. `verified` нельзя ставить без источника, даты, объёма проверки и оснований публикации персональных данных.
4. Если `trust.checked_at` пуст, карточка получает статус `needs_review`, даже если хорошо заполнена технически.
5. `recheck_after` нельзя заполнять без `checked_at`.
6. `publication_consent_ref` не должен содержать скан согласия, подпись, телефон или текст закрытой переписки.
7. В публичном репозитории хранятся только обезличенные ссылки. Исходные доказательства должны находиться в закрытом хранилище.

## Пример частичной проверки

```json
{
  "verification_status": "partial",
  "trust": {
    "source_type": "direct_confirmation",
    "source_ref": "source:tos-bogana:2026-07-15:01",
    "checked_at": "2026-07-15",
    "checked_by": "portal-editor",
    "recheck_after": "2027-01-15",
    "verification_scope": ["chairperson", "phones", "social_links"],
    "publication_consent_ref": "consent:tos-bogana:2026-07-15:01"
  }
}
```

Этот пример показывает только структуру. Его нельзя копировать в реальную карточку без фактического подтверждения.
