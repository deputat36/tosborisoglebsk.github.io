# Управление публичной поверхностью портала ТОС БГО

Дата введения политики: 12 июля 2026 года.

## Зачем нужна политика

Количество публичных страниц портала уже значительно превышает объём подтверждённого фактического контента. До закрытия P0 нельзя создавать новые корневые публичные разделы только ради заполненности, SEO или отдельного рабочего сценария.

Политика не удаляет существующие страницы и не мешает публиковать:

- новые карточки ТОС внутри `/tos/`;
- новые новости внутри `/news/`;
- подтверждённые проекты внутри `/projects/`;
- потребности внутри `/needs/`;
- результаты внутри `/done/`;
- материалы внутри существующих разделов.

## Что считается новым корневым публичным разделом

Новый файл вида:

```text
new-section/index.html
```

который:

- индексируется поисковыми системами;
- создаёт новый URL первого уровня `/new-section/`;
- не является служебным `noindex`-инструментом.

## Что разрешено без отдельного решения

- изменение существующей страницы;
- новая детальная страница внутри существующего раздела, например `/news/example/`;
- новый внутренний инструмент с `noindex,nofollow`;
- генерация карточек из существующих структурированных коллекций;
- исправление маршрутов, доступности, SEO и контента существующих страниц.

## Что требует явного решения

Новый корневой публичный раздел должен одновременно иметь:

1. запись в `data/public_section_registry.json`;
2. статус `approved`;
3. аудиторию;
4. одну конкретную пользовательскую задачу;
5. владельца сопровождения;
6. ссылку на issue, PR или другое решение;
7. маркер `data-public-section-approved` в HTML.

Пример записи:

```json
{
  "path": "example/index.html",
  "route": "/example/",
  "status": "approved",
  "audience": "жители",
  "user_task": "найти подтверждённую информацию о ...",
  "owner": "portal-editor",
  "decision_ref": "issue:#000"
}
```

## Почему служебные страницы не блокируются

Редакционные и технические инструменты могут появляться автономно, если:

- они закрыты через `noindex,nofollow`;
- не включаются в массовую публичную навигацию;
- не содержат закрытых данных;
- проходят route-governance и accessibility-аудиты.

## Работа CI

`scripts/audit_public_surface_changes.js` сравнивает текущую ветку с базовой и ищет добавленные корневые `index.html`.

Если новый корневой раздел индексируется, CI требует запись в реестре и маркер согласования. Без них PR блокируется.

## Ограничение политики

Политика контролирует рост архитектуры, но не определяет юридическую или фактологическую достоверность содержания. Новая страница даже после архитектурного согласования должна пройти обычные проверки источников, персональных данных, SEO и доступности.
