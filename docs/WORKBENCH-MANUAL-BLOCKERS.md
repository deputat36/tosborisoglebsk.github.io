# Ручные блокеры в рабочей панели

Дата обновления: 16 июля 2026 года.

## Назначение

Рабочая панель `/workbench/` показывает компактную сводку пяти открытых задач, которые нельзя завершить только автоматическим аудитом:

- #34 — подтверждение четырёх приоритетных карточек ТОС;
- #164 — ручная проверка GitHub Pages;
- #166 — фактическое исполнение 15 исходящих запросов;
- #205 — восемь организационных и юридических решений;
- #254 — проверка оснований публикации для 24 карточек.

Полная версия сводки остаётся на странице `/github-tasks/`.

## Источники

Блок читает только канонические файлы репозитория:

- `data/verification_readiness_matrix.csv`;
- `data/github_pages_manual_check_template.csv`;
- `data/outreach_register.csv`;
- `data/personal_data_decision_packet.csv`;
- `data/publication_basis_confirmation_register.csv`.

Счётчики рассчитываются тем же модулем `assets/js/manual-blocker-summary.js`, который используется центром ручных блокеров.

## Что выполняется в браузере

Модуль:

1. добавляет служебный раздел после hero-блока рабочей панели;
2. загружает существующие read-only валидаторы;
3. читает пять CSV через обычные GET-запросы;
4. показывает прогресс, готовые действия и ошибки структуры;
5. ведёт к профильным инструментам каждой задачи.

Никакие данные из блока не отправляются обратно на сервер или в GitHub.

## Граница доверия

Отображение зелёного статуса проверки означает только корректность структуры и выполнение формальных условий соответствующего CSV.

Блок не может:

- отправлять сообщения;
- отмечать запрос как `sent`, `waiting` или `received`;
- подтверждать карточку ТОС;
- назначать ответственного или проверяющего;
- выбирать юридическое основание;
- создавать `publication_consent_ref`;
- подтверждать настройки GitHub Pages;
- закрывать GitHub Issue.

Фактические действия фиксируются только после их реального выполнения и отдельной проверяемой записи.

## Загрузка модуля

Страница `/workbench/` уже подключает `assets/js/workbench-drafts.js`. Этот изолированный файл добавляет загрузчик `assets/js/workbench-manual-blockers.js`.

Модуль проверяет наличие блока и загрузчика, поэтому повторное подключение не создаёт дубликаты.

## Проверка

Аудит должен подтверждать:

- наличие пяти карточек и правильный порядок issue;
- ссылки на все профильные инструменты;
- использование пяти канонических CSV;
- использование существующих валидаторов и общего summary-модуля;
- отсутствие `POST`, `PUT`, `PATCH`, `DELETE`, `sendBeacon`, `WebSocket` и `XMLHttpRequest`;
- read-only permissions профильного workflow;
- включение проверки в общий ручной аудит.

Автоматический аудит подтверждает только целостность инструмента. Он не подтверждает выполнение внешних задач.
