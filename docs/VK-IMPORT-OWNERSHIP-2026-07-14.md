# Импорт новостей из ВКонтакте

Дата: 14 июля 2026 года. Актуализировано: 4 сентября 2026 года.

## Единственный scheduled VK workflow

Единственным владельцем автоматического импорта является `.github/workflows/update-vk-news.yml`.

Workflow запускается:

- вручную через `workflow_dispatch`;
- по расписанию каждые шесть часов;
- только в рабочей ветке `release-2025-12-22`.

Второй scheduled workflow недопустим: два задания могут одновременно обращаться к VK API, создавать разные форматы данных и выполнять конкурирующие автоматические коммиты.

## Поддерживаемый маршрут

Поддерживаемая цепочка:

`update-vk-news.yml` → `scripts/import_vk_news.js` → `data/news.json` → страницы `/news/` → зависимые материалы → `sitemap.xml`.

После импорта workflow:

1. синхронизирует происхождение контента;
2. обновляет отчёт происхождения;
3. регенерирует страницы новостей;
4. регенерирует зависимые материалы;
5. обновляет sitemap;
6. проверяет происхождение, внутренние ссылки и SEO;
7. коммитит только перечисленные сгенерированные файлы.

## Удалённый legacy-контур

Старый маршрут `.github/workflows/import-vk-posts.yml` → `scripts/import_vk_posts.js` создавал отдельный файл, который не участвовал в публичной генерации.

`data/vk_posts.json` не используется и не должен появляться в репозитории. Его отсутствие не является потерей публичных данных: канонической коллекцией новостей остаётся `data/news.json`.

## Редакционная граница

Импортируются не все записи сообщества. `scripts/import_vk_news.js` принимает только публикации с одним из разрешённых служебных хештегов.

Хештег является редакционным разрешением на импорт, а не доказательством достоверности всех утверждений внутри публикации. После импорта сохраняются ссылка на оригинал, идентификаторы VK и признаки происхождения.

Закреплённые публикации исключаются. Существующие VK-записи объединяются по стабильному VK ID, чтобы повторный запуск обновлял запись, а не создавал дубль.

## Секреты и переменные

- `VK_TOKEN` хранится только в GitHub Secrets и остаётся единственной обязательной закрытой настройкой;
- для вызова `wall.get` нужен совместимый пользовательский либо сервисный access token; group/community access token возвращает VK API error 27 и не подходит для этого метода;
- текущий внешний блокер совместимости токена зафиксирован в GitHub Issue #350; значение токена нельзя публиковать в Issue, документации, JSON, HTML или логах;
- `VK_DOMAIN` можно задать через GitHub Actions Variables для переопределения источника; если переменная пустая, импортёр использует публичный домен рабочего сообщества `tosbgo` (`https://vk.ru/tosbgo`);
- `VK_OWNER_ID` необязателен и при наличии используется как явный ID сообщества;
- `VK_HASHTAGS`, `VK_COUNT` и `NEWS_LIMIT` можно задавать через GitHub Actions Variables; при отсутствии используются значения по умолчанию импортёра;
- токен и закрытые значения не записываются в JSON, HTML или логи проекта;
- секреты нельзя переносить в публичные файлы репозитория.

Публичный fallback `tosbgo` не является секретом: эта ссылка уже используется порталом как рабочее сообщество. Такой fallback нужен, чтобы scheduled workflow не падал только из-за отсутствующей repository variable `VK_DOMAIN`, сохраняя возможность явного переопределения через Actions Variables.

## Retention и защита канонического контента

`NEWS_LIMIT` ограничивает только количество записей с `imported_from: "vk"`. Он не применяется ко всей коллекции `data/news.json` и не может удалять старые source-backed, editorial, starter или request-материалы портала.

Алгоритм импорта:

1. загружает всю существующую каноническую коллекцию;
2. обновляет или добавляет VK-записи по стабильному ID;
3. отделяет `imported_from: "vk"` от остальных материалов;
4. применяет `NEWS_LIMIT` только к VK-части;
5. возвращает все канонические записи плюс разрешённое число VK-записей, отсортированные по дате.

Regression-test моделирует коллекцию более чем из 100 канонических материалов и отдельно проверяет, что даже при малом `NEWS_LIMIT` ни один non-VK материал не исчезает.

## Автоматическая защита

`scripts/audit_vk_workflow_topology.js` блокирует изменения, если:

- найдено больше одного scheduled VK workflow;
- владельцем `scripts/import_vk_news.js` является не `update-vk-news.yml`;
- возвращены ссылки на `import_vk_posts.js` или `data/vk_posts.json`;
- нарушена граница Secrets/Variables;
- удалён public fallback `tosbgo`;
- удалён hashtag allowlist;
- `NEWS_LIMIT` снова начинает обрезать всю каноническую коллекцию вместо VK-части;
- topology audit запускается после сетевого импорта;
- из workflow исчезают генераторы или обязательные проверки;
- audit не подключён к package и project-mode.

`scripts/test_vk_workflow_topology.js` проверяет дублирующий workflow, legacy importer, legacy data target, importer без allowlist, отсутствие публичного fallback и retention-контракт, сохраняющий все non-VK новости.

## Evidence и публикация

Успешный PR-CI не доказывает, что scheduled run основной ветки выполнился и создал новый commit. После слияния отдельно проверяются:

- push-run рабочей ветки;
- следующий scheduled run `Update VK news`;
- conclusion job;
- прохождение шага `Import VK posts to news.json` без error 27;
- наличие или отсутствие изменений в `data/news.json`;
- автоматический commit, если были новые разрешённые публикации;
- GitHub Pages deployment и внешние URL.

Отсутствие нового commit после успешного scheduled run допустимо, если подходящих новых публикаций с разрешённым хештегом не было.
