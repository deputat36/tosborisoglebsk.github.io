# Импорт новостей из ВКонтакте

Актуальная редакция: 13 ноября 2026 года.

## Единственный scheduled VK workflow

Единственный владелец — `update-vk-news.yml`, рабочая ветка `release-2025-12-22`.
По поручению владельца от 13.11.2026 импортируются **все доступные публичные посты и репосты** стены общего сообщества, включая закреплённую запись. Служебный разрешающий хештег больше не нужен. Проверка — каждый час, вручную через workflow_dispatch и при изменении импортёра/его задания/файла управления. GitHub может задерживать cron; это не обещание публикации ровно в начале часа.

## Правила для председателей

- Опубликуйте пост или репост в общей группе: дополнительного действия для сайта не требуется.
- Чтобы не размещать запись на сайте, добавьте **`#неНаСайтТОСБГО`**. Регистр не важен; учитывается целый тег, в том числе в исходном тексте репоста. При следующем успешном обходе ранее импортированная запись будет снята.
- Для привязки к карточке ТОС используйте его однозначный хештег, например `#ТОСБогана`. Отсутствие такого тега не мешает импорту в общую ленту. По неясному названию принадлежность не угадывается.
- Сохраняются дата публикации в группе (Москва), комментарий автора репоста, исходный текст и ссылка на оригинал. Повторная синхронизация обновляет прежний ID.
- Исторические объявления остаются архивом с исходной датой; это не подтверждение актуальности конкурса или мероприятия сегодня.

## Архив и восстановление

Каноническая коллекция — `data/news.json`, **без ограничения архива**. `NEWS_LIMIT` больше не используется, в том числе если старая переменная осталась в репозитории. Не относящиеся к ВК редакционные записи сохраняются.

`VK_COUNT` — размер одной страницы API (1–100; по умолчанию 100), а не число переносимых новостей. Последовательные запросы wall.get с offset и filter=all обходят всю доступную стену. Повторные ID, в том числе закреплённые записи, объединяются. Каждая полная синхронизация также обновляет тексты и ссылки старых публикаций.

`data/vk_import_pending.json` хранит промежуточные публичные записи и offset. На ошибке рабочая коллекция не меняется; задание сохраняет checkpoint отдельным коммитом. Следующий запуск повторно проверяет перекрытие двух страниц и продолжает. По умолчанию максимум 100 страниц за запуск (10 000 записей), далее следующий запуск продолжает; `VK_MAX_PAGES` — 1–1000. После завершения checkpoint равен null. При изменении источника/режима/размера страницы/хештегов старый checkpoint не используется.

`data/vk_sync_state.json` хранит сведения успешной сверки и подтверждения исчезновения. Запись снимается после двух полных успешных обходов, где она отсутствует. При массовом исчезновении более 20% прежнего архива автоматическое удаление блокируется; причина фиксируется как deletion_review. Пустой/некорректный ответ до конца стены, ошибка сети или API не являются доказательством удаления. Контроль доступен в `data/vk_import_report.json`: количество ВК, уникальных записей, исключений, репостов и медиа. Число API и число уникальных ID показываются отдельно из-за возможных закреплений/изменений стены во время обхода.

## Медиа остаются в ВК

Фотографии, превью и документы не скачиваются в репозиторий и не копируются в платное хранилище. В JSON сохраняются только публичные ссылки и размеры. Для ленты используется уменьшенное превью, для страницы — подходящий размер, по нажатию открывается оригинал. Галерея не обрезается первыми восемью фото.

Видео получает официальный проигрыватель только при наличии допустимого player URL в ответе ВК. В остальных случаях показываются доступное превью и ссылка на видео ВК. Документы, аудио и внешние ссылки открываются по адресам источника. Опросы, клипы и другие интерактивные вложения доступны через исходную запись; собственный проигрыватель или копия содержимого не имитируются. Закрытые и удалённые материалы недоступны через публичный API; ссылки/медиа зависят от доступности ВК.

## Единая публикация

Импортёр не генерирует отдельную упрощённую HTML-версию. `scripts/publish_vk_archive.js` последовательно обновляет происхождение, новости, материалы, карточки ТОС, статический архив по 24 записи, «Мою территорию», главную, RSS, версии скриптов, поиск и sitemap. Затем проверяются источники, удаление устаревших сгенерированных страниц, внутренние ссылки и SEO. Задание коммитит только успешный результат. Ни одна публикация ВК автоматически не получает статус проверенного результата проекта; для неё показана подпись «Из сообщества ВКонтакте».

## Секреты и история настройки

`VK_TOKEN` хранится только в GitHub Secrets. Токен передаётся API в POST, отсутствует в адресах, файлах, ошибках и отчётах. Совместим сервисный или пользовательский токен; group/community access token даёт error 27. Прежний блокер отражён в #350; 13.11.2026 успешный реальный запуск уже подтвердил доступ к wall.get. Значение ключа не читается и не публикуется.

Источник по умолчанию: `tosbgo` (https://vk.ru/tosbgo). `VK_DOMAIN` и отрицательный `VK_OWNER_ID` — открытые Variables. В рабочем задании явно установлен VK_IMPORT_MODE=all; чистые функции сохраняют optional tagged-режим для обратной совместимости. `VK_HASHTAGS` имеет значение только для tagged-режима и очистки служебных тегов. Стоп-метка явно закреплена в задании.

`data/vk_posts.json` не используется. Старые import-vk-posts.yml/import_vk_posts.js не восстанавливаются.

## Проверки и доказательство работы

Автопроверки блокируют второго владельца, возвращение legacy-маршрута, утрату стоп-метки, полного обхода, checkpoint или сохранности редакционных записей. Тестируются более 50/100 публикаций, репосты, закрепление, точные хештеги, Москва, временные ошибки, восстановление, небезопасные URL, плееры и повторное подтверждение удаления.

Успешный PR-CI не доказывает боевой перенос. После слияния проверяются реальный Update VK news, счётчики ответа API, уникальные IDs/даты, бот-коммит, Pages и открывающиеся страницы/медиа. Не выдавать состояние архив_complete за доказательство доступности скрытых записей ВК.
