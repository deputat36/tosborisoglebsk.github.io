# Модель безопасности локального редактора `/admin/`

Дата: 14 июля 2026 года.

## Статус

`/admin/` — публичный клиентский локальный редактор открытых JSON-данных портала.

Он не является серверной авторизацией, закрытой административной зоной или системой разграничения доступа. Наличие страницы по пути `/admin/`, `localStorage`, скрытой ссылки, PIN в JavaScript или клиентской проверки не создаёт серверную защиту.

## Что делает редактор

- выполняет GET-запросы только к открытым `/data/*.json` на том же сайте;
- сохраняет рабочие черновики в `localStorage` текущего браузера;
- принимает локальный JSON-файл через `FileReader`;
- создаёт локальные Blob-файлы для скачивания;
- не записывает изменения в GitHub;
- не отправляет данные на сторонние серверы;
- не создаёт пользователя, сессию или роль.

## Что запрещено

В редакторе и публичном репозитории не допускаются закрытая переписка, паспорта, подписи, банковские данные, оригиналы согласий, внутренние списки, непубличные контакты, секретные ссылки, API-ключи, токены и пароли.

Даже если такие сведения временно введены в форму, они могут сохраниться в `localStorage` и остаться доступными другим пользователям устройства. После работы на общем компьютере локальные черновики нужно удалить.

## Сетевые ограничения

Активная страница использует Content Security Policy:

- `default-src 'self'`;
- `connect-src 'self'`;
- `script-src 'self'`;
- `object-src 'none'`;
- `form-action 'none'`.

Целевые показатели блокирующего аудита:

- external network targets: 0;
- write signals: 0;
- dangerous execution signals: 0;
- potential secrets: 0;
- Supabase references: 0;
- missing local references: 0;
- JavaScript syntax failures: 0.

## Индексация

- каждый HTML-файл в `/admin/` обязан иметь `noindex,nofollow`;
- `robots.txt` обязан содержать `Disallow: /admin/`;
- sitemap не должен содержать URL `/admin/`;
- устаревшие HTML-входы должны вести на `/admin/`, а не загружать отдельный набор скриптов.

## Публикационный процесс

Редактор готовит только локальный файл. Публикация выполняется отдельным контролируемым изменением:

1. скачать JSON;
2. проверить diff;
3. проверить источники и допустимость публикации персональных сведений;
4. заменить файл в `data/`;
5. запустить CI;
6. проверить публичную страницу и сгенерированные данные.

Скачанный файл не получает статус проверенного или юридически допустимого автоматически.

## Машиночитаемый контроль

`data/admin_surface_inventory.json` создаётся скриптом `scripts/generate_admin_surface_inventory.js` и содержит только:

- пути и роли файлов;
- размеры и SHA-256;
- локальные зависимости;
- агрегированные сигналы безопасности;
- состояние noindex, CSP, robots и sitemap.

Значения пользовательских черновиков в отчёт не попадают.

`scripts/audit_admin_surface.js` пересобирает отчёт, сравнивает его с сохранённой версией и блокирует CI при изменении модели безопасности.
