# Проверка восьми малых кандидатов PR №220

Дата: 14 июля 2026 года.

## Принцип

Ни один файл не переносится из старой ветки напрямую. Для каждого кандидата проверена цель старого patch относительно актуального `release-2025-12-22`.

## Решения

| Путь | Решение | Причина |
|---|---|---|
| `assets/js/home-stats.js` | Уже реализовано в main | Текущий код уже использует порядок `label, value, hint` и корректно выводит значение в `<b>` |
| `data-requests/priority-tos/index.html` | Принять noindex | Страница является редакционным инструментом подготовки запросов, а не публичным содержательным разделом |
| `data-requests/tos-registry-request/index.html` | Принять noindex | Страница содержит рабочие шаблоны обращения и не должна конкурировать с публичными разделами |
| `llms.txt` | Переклассифицировать | `/data-requests/` удаляется из публичных методических ссылок и явно перечисляется среди рабочих страниц |
| `scripts/audit_actions_check_content.js` | Переписать отдельно | Старый patch заменяет одну фиксированную дату, SHA и счётчики другими уже устаревшими значениями; нужен динамический контракт |
| `scripts/audit_homepage_content.js` | Принять regression-guard | Исправление статистики уже находится в main, но отдельная проверка не позволяет снова поменять label и value местами |
| `scripts/audit_priority_tos_readiness.js` | Отклонить старый patch | Текущая архитектура использует статический якорь `#priority-tos-readiness`; удаление якоря ослабит навигационный контракт |
| `scripts/audit_route_governance.js` | Принять noindex-guard | Машинная проверка закрепляет редакционный статус двух страниц запросов |

## Принятые изменения

1. Обе страницы запросов получают `noindex,nofollow`.
2. `llms.txt` перестаёт выдавать `/data-requests/` за публичный методический раздел.
3. `patch_llms_links.js` больше не восстанавливает удалённую публичную ссылку.
4. Homepage audit проверяет правильный порядок полей статистики.
5. Route governance audit проверяет noindex обеих страниц.

## Отклонённые изменения

### Readiness anchor

Старый patch заменял ссылку `/data-requests/priority-tos/#priority-tos-readiness` на корень страницы. В текущем main:

- секция `id="priority-tos-readiness"` существует статически;
- клиентский код заполняет именно эту секцию;
- site-health использует точный якорь;
- audit запрещает динамическое создание секции.

Поэтому старое изменение не применяется.

### Статический Actions audit

Старый patch просто менял:

- дату 2 июля на 13 июля 2026 года;
- 369 страниц на 371;
- старый SHA на другой старый SHA;
- ID строк diagnostics.

На 14 июля эти значения уже нельзя считать актуальным решением. Отдельная задача должна убрать зависимость от вручную зашитых дат, SHA и счётчиков.

## Границы

- тексты самих запросов не изменяются;
- факты отправки не создаются;
- данные ТОС не меняются;
- readiness anchor сохраняется;
- Actions audit не маскируется новыми статическими значениями;
- изменения выполняются от актуального main, без cherry-pick PR №220.
