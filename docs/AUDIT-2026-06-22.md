## Что уже сильное

### 1. Понятная структура портала

На сайте есть основные публичные разделы: каталог ТОС, новости, проекты, потребности, календарь, результаты, документы, правовые материалы и справочные страницы.

### 2. Есть практические маршруты

Портал объясняет не только «что такое ТОС», но и что делать конкретному человеку: председателю, жителю, партнёру, инициативной группе, автору проекта или организатору события.

### 3. Есть рабочий контур редактора

Раздел `/workbench/` и связанные рабочие страницы помогают видеть пробелы, готовить сообщения, выгружать CSV и контролировать качество карточек.

### 4. Есть автоматическая проверка качества

`data/site_health.json` показывает состояние страниц, внутренних ссылок, SEO и каталога. Это хорошая основа для регулярного контроля.

### 5. Рабочие страницы отделены от публичных

Служебные страницы закрыты от индексации. Это снижает риск, что поисковые системы будут показывать пользователям технические страницы вместо нормальных публичных разделов.

## Главные проблемы

### 1. Нет подтверждённых карточек

В каталоге 24 ТОС, но `verified_count` равен 0. Для общественного портала это главный риск: посетитель должен понимать, какие сведения подтверждены, а какие требуют уточнения.

### 2. Четыре карточки требуют первоочередной работы

Высокий приоритет сейчас у четырёх ТОСов:

- Ивановка;
- Подстёпки;
- Губари;
- Танцырей.

У Ивановки и Подстёпок нет телефона, email, соцсетей и логотипа. У Губарей и Танцырея нет телефона и логотипа.

### 3. Много SEO-предупреждений

В отчёте 67 SEO-предупреждений. Это не ломает сайт, но мешает аккуратной публикации: у части страниц короткие или длинные описания, отсутствуют canonical или Open Graph-поля.

### 4. Нужен более строгий редакционный процесс

Сейчас есть черновики и рабочие страницы, но следующий уровень — понятная цепочка: получили сведения, проверили источник, внесли изменение в JSON, открыли PR, проверили генерацию, смержили.

### 5. CSS и часть JS становятся сложнее для сопровождения

`assets/css/styles.css` трудно проверять при больших изменениях, если файл хранится в сжатом виде. Рабочие скрипты тоже постепенно растут. Это не срочно, но лучше не откладывать до момента, когда правки станут рискованными.

## Что улучшать первым

### Приоритет 1. Доверие к карточкам

1. Использовать задачу #34 и `/data-requests/` для запроса сведений по четырём приоритетным ТОСам.
2. Получить подтверждение телефона, публичной ссылки, источника и даты проверки.
3. После подтверждения обновить `data/toses.json` и связанные поля проверки.
4. Переводить карточку в `verified` только при наличии источника.

### Приоритет 2. SEO-предупреждения

1. Сначала исправить шаблоны документов и методические материалы.
2. Затем пройти потребности и результаты с длинными описаниями.
3. После каждой пачки запускать генерацию и проверять `data/site_health.json`.

### Приоритет 3. Редакционный процесс

1. Описать путь публикации: сообщение от председателя → проверка → JSON → PR → генерация → публичная карточка.
2. В `/workbench/` постепенно добавить подсказки для этого процесса.
3. Не хранить важные рабочие сведения только в localStorage, если они должны стать частью архива проекта.

### Приоритет 4. Сопровождаемость кода

1. Отформатировать или разделить `assets/css/styles.css`.
2. Не добавлять новые крупные блоки в один общий файл без необходимости.
3. При росте `/workbench/` разделить JS по задачам: аудит, фильтры, черновики, экспорт.

## Что не делать сейчас

- Не добавлять новые большие разделы без необходимости.
- Не менять фактические данные ТОС без подтверждения.
- Не переводить карточки в `verified` вручную «для красоты статистики».
- Не удалять защиту старых ссылок, пока не будет устойчивой проверки всех сгенерированных страниц.
- Не тратить время на декоративную переработку дизайна до подтверждения базовых данных.
