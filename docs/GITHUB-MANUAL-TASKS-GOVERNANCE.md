# Governance ручных блокеров

## Назначение

`data/github_manual_tasks.csv` и `/github-tasks/` показывают только те задачи, которые требуют внешнего действия, официального источника, ручной проверки или решения пользователя.

Реестр не обращается к GitHub API во время CI и не считается автоматической копией Issues. GitHub Issues остаются первичным источником фактического статуса, а локальный снимок обновляется отдельным проверяемым PR.

## Текущий набор

В локальном реестре закреплены открытые issues #34, #164, #166, #205 и #254, а также служебная строка `0` для `data/user_decision_queue.csv`.

Закрытая issue #165 не является открытым блокером и не должна возвращаться в CSV или карточки `/github-tasks/`. Требование visual comparison сохраняется как общее правило сопровождения, но больше не связывается с открытой issue #165.

## Контракт данных

Для каждой строки обязательны:

- уникальный `issue_number`;
- точное название актуальной задачи;
- поддерживаемая группа и статус;
- существующий локальный инструмент;
- существующий CSV или JSON-источник;
- проверяемый критерий завершения;
- конкретное следующее действие;
- дата актуализации.

Для issues #34, #164, #166, #205 и #254 статус должен оставаться `open`, пока соответствующая GitHub Issue реально не закрыта.

## Контракт страницы

Каждая открытая issue представлена ровно одной карточкой с атрибутом `data-manual-issue`. Порядок карточек фиксирован: 34, 164, 166, 205, 254.

Страница должна честно отражать границы:

- public smoke не заменяет ручную проверку Settings → Pages;
- подготовленный запрос не считается отправленным;
- технический audit не создаёт официальный источник;
- обычный ответ не создаёт согласие на распространение;
- режим `pre_legal_readiness` сохраняется до юридического решения.

## CI

`scripts/audit_github_manual_tasks.js` проверяет CSV, страницу, npm-команды, project-mode, документацию и read-only workflow.

`scripts/test_github_manual_tasks.js` доказывает отрицательные сценарии:

- возвращение закрытой issue #165;
- потеря обязательной issue #205;
- возврат устаревшего объяснения #164;
- удаление строки очереди решений.

`.github/workflows/manual-tasks-governance.yml` работает в режиме read-only и не изменяет Issues, CSV или HTML.

## Порядок обновления

1. Проверить фактическое состояние GitHub Issue.
2. Изменить локальный CSV и связанную очередь решений.
3. Обновить карточки `/github-tasks/`.
4. Запустить self-test, audit и full project-mode.
5. Зафиксировать результат небольшим PR.

Нельзя закрывать внешний блокер только потому, что обновлена служебная страница или создан новый шаблон.
