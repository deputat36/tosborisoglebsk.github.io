# Консолидация локальной админ-панели

Дата: 13 июля 2026 года.

## Причина

В каталоге `admin/` накопились две HTML-версии редактора и несколько JavaScript-модулей, которые выполняли одинаковые массовые операции.

Основная страница `/admin/` одновременно подключала:

- `admin-logo-tools.js`;
- `admin-logo-bulk.js`.

Оба модуля добавляли кнопки массового формирования путей логотипов и CSV записей без логотипа. Отдельная страница `admin-index-ready.html` дополнительно подключала три почти одинаковых варианта массового автозаполнения.

Это приводило к повторяющимся кнопкам, разным формулировкам одного действия и риску расхождения логики.

## Поддерживаемая реализация

Оставлена одна страница:

- `admin/index.html`.

После безопасного функционального расширения поддерживается одна HTML-страница и пять модулей в фиксированном порядке:

1. `admin/admin2.js` — основной редактор, поиск, фильтры, импорт и JSON-экспорт;
2. `admin/admin-logo-tools.js` — фильтр без логотипа, массовые пути и CSV;
3. `admin/admin-dashboard.js` — обзор данных и проблемных мест;
4. `admin/admin-export-tools.js` — CSV текущей отфильтрованной выборки;
5. `admin/admin-history.js` — локальные снимки и восстановление последнего состояния.

Новые безопасные инструменты не возвращают дублирующие реализации и не изменяют основную логику редактора.

## Удалённые файлы

- `admin/admin-index-ready.html`;
- `admin/admin.js`;
- `admin/admin-logo-bulk.js`;
- `admin/admin-mass-autofill.js`;
- `admin/admin-mass-fill-all.js`;
- `admin/admin-mass-all-autofill.js`.

Содержимое сохраняется в Git history и при необходимости может быть изучено без поддержки нескольких рабочих копий.

## Служебная очистка

- удалён несуществующий `admin/admin-index-ready.html` из SEO skip-list;
- accessibility patcher работает только с `admin/index.html` и `tools/import.html`;
- JavaScript syntax-check охватывает каталог `admin/`;
- изменения `admin/**` запускают основной GitHub Actions workflow.

## Безопасность

Админка остаётся локальным статическим инструментом:

- `noindex,nofollow`;
- не хранит GitHub token;
- не обращается к `api.github.com`;
- не делает commit или push;
- сохраняет черновики и историю в браузере;
- создаёт CSV и JSON локально;
- скачивает файлы для последующей ручной публикации через репозиторий и CI.

Прямая запись в GitHub намеренно не используется. Для неё потребовались бы отдельный защищённый backend, авторизация, журналирование и ограниченные права.

## Автоматическая защита

`scripts/audit_admin_consolidation.js` проверяет:

- наличие единственной поддерживаемой страницы;
- ровно пять подключённых модулей и их порядок;
- отсутствие дублирующихся script-src;
- отсутствие шести удалённых файлов;
- отсутствие ссылок на удалённые файлы в HTML и служебных скриптах;
- noindex-режим;
- предупреждение о ручной публикации;
- отсутствие клиентских credential/API patterns;
- включение каталога `admin/` в JavaScript syntax-check.

`scripts/audit_admin_safe_tools.js` отдельно проверяет CSV-экспорт, локальные снимки, лимит истории, резерв перед откатом и отсутствие сетевой отправки данных.

## Границы пакетов

Первый пакет консолидации не добавлял функции редактора. Второй stacked-пакет добавляет только локальный CSV и историю снимков, не меняя JSON-схемы или публичные данные. Редактирование дополнительных коллекций должно оформляться отдельным PR со schema-аудитом.
