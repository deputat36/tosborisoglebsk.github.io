## 56. Машинная проверка редакционного календаря

- добавлен аудит `data/editorial_calendar.csv`;
- проверяются заголовки, допустимые периоды, статусы, типы задач, источники, следующий шаг и отсутствие дублей по паре `period` + `content_type`;
- маршруты и файлы из `target_page_or_file` проверяются на существование в репозитории;
- для статусов `ready` и `done` требуется ответственный `owner`;
- заблокированные задачи должны явно объяснять блокирующее действие;
- проверка подключена к `scripts/audit_project_mode.js` и `scripts/audit_project_mode_full.js`.

## Практический эффект

Редакционный календарь теперь не может незаметно потерять ключевые регулярные задачи: мониторинг источников, новости, карточки ТОС, QA публикаций, реестр, медиа и квартальный отчёт. Если удалить целевую страницу или CSV, общий audit-runner должен показать ошибку до публикации.

## Ограничения

- публичные данные и факты не менялись;
- календарь остаётся рабочим планом, а не подтверждением выполнения задач;
- фактическая отправка запросов, проверка GitHub Actions UI и получение официального реестра остаются внешними действиями.
