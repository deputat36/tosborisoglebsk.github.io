# Безопасная очистка автогенерируемых страниц

Дата: 14 июля 2026 года.

## Проблема

Генераторы создают детальные страницы из JSON, но раньше не удаляли каталог, если запись удалена из данных или переведена в `draft`. В результате старая HTML-страница могла оставаться доступной, попадать в технические проверки и показывать уже неактуальный материал.

## Охваченные коллекции

Очистка работает для пяти наборов:

1. `data/toses.json` → `/tos/{slug}/`;
2. `data/articles.json` → `/materials/{id}/`;
3. `data/news.json` → `/news/{id}/`;
4. `data/done.json` → `/done/{id}/`;
5. `data/needs.json` → `/needs/{id}/`.

Опубликованной считается запись с непустым идентификатором и `status`, отличным от `draft`. Это совпадает с действующей логикой генераторов.

## Защита ручных страниц

Каталог удаляется только при одновременном выполнении всех условий:

- он находится внутри корня одной из пяти коллекций;
- его имя отсутствует среди опубликованных идентификаторов JSON;
- внутри есть `index.html`;
- `index.html` содержит точный маркер соответствующего генератора.

Если маркера нет, каталог считается ручным и сохраняется. Индекс коллекции, файлы в корне, пустые каталоги и директории без `index.html` не удаляются.

## Pipeline

Перед генерацией детальных страниц workflow запускает:

```text
node scripts/test_generated_page_cleanup.js
node scripts/cleanup_generated_collection_pages.js
```

После генераторов выполняется блокирующая строгая проверка:

```text
GENERATED_PAGE_CLEANUP_STRICT=true node scripts/audit_generated_page_cleanup.js
```

Строгий режим проверяет отсутствие stale-каталогов уже после cleanup и повторной генерации. Обычный project-mode запускает тот же audit в integration-режиме: проверяет helper, маркеры, конфигурацию и подключение к CI, но не изменяет checkout профильных read-only workflow.

Изменения в `scripts/lib/**` запускают основной workflow благодаря пути `scripts/**/*.js`.

## Автоматическая защита

- `scripts/lib/generated_page_cleanup.js` содержит только поиск и удаление каталогов с подтверждённым маркером;
- `scripts/lib/generated_collection_pages.js` хранит единый список коллекций, ключей и маркеров;
- `scripts/test_generated_page_cleanup.js` доказывает сохранение актуальных и ручных страниц;
- `scripts/audit_generated_page_cleanup.js` в strict-режиме блокирует оставшиеся stale-страницы, а в integration-режиме проверяет контракт;
- аудит включён в обычный и полный project-mode без изменения файлов;
- строгая проверка выполняется только основным генерационным pipeline после cleanup.

## Границы

Пакет не меняет JSON, публичные тексты и шаблоны страниц. Он не удаляет проекты и другие каталоги, где действует отдельная логика legacy-redirects. Удаление ручных страниц без маркера намеренно запрещено.
