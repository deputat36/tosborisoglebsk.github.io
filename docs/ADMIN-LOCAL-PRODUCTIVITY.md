# Локальные рабочие функции admin-редактора

Дата проверки: 14 июля 2026 года.

## Назначение

Пакет расширяет безопасную модель PR №256 только локальными функциями браузера. `/admin/` остаётся публичным клиентским редактором без серверной авторизации, аккаунтов и прямой записи в репозиторий.

Редактор предназначен для подготовки и проверки открытых JSON-файлов перед отдельным контролируемым изменением GitHub-репозитория.

## Поддерживаемые коллекции

Редактор работает с девятью открытыми наборами:

1. `data/toses.json`;
2. `data/news.json`;
3. `data/articles.json`;
4. `data/documents.json`;
5. `data/grants.json`;
6. `data/projects.json`;
7. `data/done.json`;
8. `data/events.json`;
9. `data/needs.json`.

`data/done.json` редактируется через отдельное описание схемы `admin/admin-done-dataset.js`. Новая запись создаётся как `draft`, имеет `content_origin: request` и явное поле с недостающими подтверждениями. Это не позволяет автоматически представить черновик подтверждённым результатом.

## CSV текущей выборки

`admin/admin-export-tools.js` экспортирует только записи, которые видны после текущего поиска и фильтра.

Экспорт:

- выполняется через браузерный `Blob`;
- не отправляет данные по сети;
- не меняет исходный JSON;
- включает все фактически присутствующие поля;
- предупреждает о необходимости проверить контакты и назначение файла перед передачей.

CSV не считается публикацией и не подтверждает достоверность сведений.

## Локальные снимки

`admin/admin-history.js` хранит до 10 снимков на каждый раздел в `localStorage`.

Снимок можно создать вручную. Автоматический снимок создаётся перед поддерживаемыми рискованными операциями: импортом JSON, добавлением, удалением, дублированием и автозаполнением.

При откате перед восстановлением старого состояния текущее состояние сохраняется как `before-restore`. Это позволяет отменить ошибочный откат в пределах доступной истории.

Ограничения:

- снимки доступны пользователям того же браузера;
- `localStorage` не является серверной защитой;
- снимки не являются резервной копией вне устройства;
- после работы на общем компьютере черновики нужно сбросить;
- перед крупной правкой следует скачать общий JSON-backup.

## Dashboard

`admin/admin-dashboard.js` читает девять разрешённых локальных GET-целей или соответствующие браузерные черновики.

Dashboard показывает структурные сигналы, но не подтверждает факты. Для результатов отдельно считаются записи, которые:

- не имеют `content_origin: verified`;
- не имеют `source_url`;
- содержат непустое `needs_details`.

Такие записи остаются задачами проверки, а не ошибками, которые можно исправить предположением.

## Модель безопасности

Не изменяются ограничения PR №256:

- серверная авторизация отсутствует;
- токены и пароли не хранятся;
- external network targets должны оставаться равными 0;
- write signals должны оставаться равными 0;
- dangerous execution signals должны оставаться равными 0;
- potential secret signals должны оставаться равными 0;
- неподключённых файлов должно оставаться 0;
- прямой commit или push из браузера запрещён;
- закрытая переписка, паспортные данные, подписи, банковские сведения, оригиналы согласий и непубличные контакты не вводятся.

Публикация выполняется только после скачивания JSON, ручной проверки diff и прохождения репозиторных аудитов.

## Машиночитаемые проверки

- `data/admin_capability_inventory.csv` — 12 возможностей и ограничений;
- `scripts/audit_admin_local_productivity.js` — поддерживаемые модули, интерфейс, локальные функции и запрет прямой публикации;
- `scripts/audit_admin_dataset_schema.js` — соответствие девяти определений фактическим JSON, уникальность ключей и допустимые `tos_slug`;
- `scripts/generate_admin_surface_inventory.js` — рекурсивный security inventory;
- `scripts/audit_admin_surface.js` — нулевые сетевые, write, secret и orphan-показатели.

## Критерии готовности

Пакет считается готовым, когда одновременно выполняются условия:

- девять вкладок и девять путей данных присутствуют;
- шесть JS-модулей подключены в установленном порядке после основного редактора;
- CSV содержит 12 уникальных capability-записей;
- прямая публикация имеет статус `intentionally_excluded`;
- все JSON-массивы валидны, ключи уникальны, `tos_slug` существуют;
- admin surface inventory соответствует файлам;
- внешний network/write/secret риск равен нулю;
- профильный read-only CI и полный project-mode проходят.
