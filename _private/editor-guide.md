# Внутренняя памятка редактора сайта ТОС БГО

Эта памятка не добавляется в меню сайта и не предназначена для обычных посетителей. Она нужна для редактора, помощника или ответственного за наполнение сайта.

Важно: репозиторий GitHub может быть публичным. Поэтому сюда нельзя добавлять пароли, токены, персональные данные, закрытые документы и служебную информацию, которую нельзя публиковать.

## 1. Основная структура данных

Данные сайта лежат в папке `data/`:

- `data/toses.json` — карточки ТОСов.
- `data/news.json` — новости.
- `data/projects.json` — проекты и идеи проектов.
- `data/events.json` — календарь событий.
- `data/needs.json` — потребности ТОСов.
- `data/articles.json` — полезные материалы.
- `data/documents.json` — документы и шаблоны.
- `data/grants.json` — конкурсы и гранты.

Страницы сайта в основном берут данные из этих JSON-файлов.

## 2. Как обновить карточку ТОС

Файл: `data/toses.json`.

Основные поля карточки:

```json
{
  "slug": "uyutnyy",
  "name": "Уютный",
  "title": "ТОС «Уютный»",
  "type": "Городской",
  "location": "г. Борисоглебск",
  "boundaries": "Уютная 1, Уютная 3...",
  "founded": "2022",
  "chairperson": "Ковтун Алексей Вадимович",
  "contacts_raw": "исходные контакты из анкеты",
  "phones": ["+7 (980) 245-74-71"],
  "emails": [],
  "chairperson_links": ["https://vk.com/borisoglebsk"],
  "groups_raw": "https://vk.com/tos_bsk",
  "social_links": ["https://vk.com/tos_bsk"],
  "population": "300",
  "description": "Описание ТОС.",
  "logo": "",
  "updated_at": "2026-05-23"
}
```

Правила:

- `slug` не менять без необходимости, от него зависит адрес страницы.
- `location` писать в едином стиле: `г. Борисоглебск`, `с. Чигорак`, `п. Ивановка`.
- `type`: только `Городской` или `Сельский`.
- Телефоны писать в формате `+7 (900) 000-00-00`.
- Если данных нет, оставлять пустой массив `[]` или пустую строку `""`.
- После изменения карточек запустить GitHub Actions: `Generate TOS pages`.

## 3. Как добавить новость

  "category": "Жизнь ТОС",
  "date": "2026-05-23",
  "tos_slug": "uyutnyy",
  "source": "ТОС «Уютный»",
  "source_url": "",

- После добавления новости запустить GitHub Actions: `Generate news pages`.

## 9. Как привязать материал к конкретному ТОС

Для связи с конкретным ТОС используется поле:

```json
"tos_slug": "uyutnyy"
```

Где `uyutnyy` — это `slug` из `data/toses.json`.

Примеры:

- новость с `tos_slug: "uyutnyy"` появится на странице `/tos/uyutnyy/`;
- проект с `tos_slug: "bogana"` появится на странице `/tos/bogana/`;
- событие с `tos_slug: "chkalovec"` появится на странице `/tos/chkalovec/`;
- потребность с `tos_slug: "gubari"` появится на странице `/tos/gubari/`.

## 10. Как запускать GitHub Actions

Открыть репозиторий → вкладка `Actions`.

Запускать нужный workflow:

- после изменения `data/toses.json` — `Generate TOS pages`;
- после изменения `data/news.json` — `Generate news pages`;
- после изменения `data/projects.json` — `Generate project pages`;
- после изменения `data/articles.json` — `Generate material pages`.

При ручном запуске:

1. Открыть нужный workflow.
2. Нажать `Run workflow`.
3. Выбрать ветку:

```text
release-2025-12-22
```

4. Запустить workflow.
5. Дождаться зелёной галочки.
6. Открыть последний запуск и проверить, что шаг `Commit generated pages, sitemap and audit` завершился без ошибки.

Для полной пересборки карточек ТОС, sitemap, аудитов и CSV-задач запускать именно `Generate TOS pages`. Он выполняет основные проверки и генераторы:

- проверку JS-синтаксиса;
- проверку JSON;
- аудит данных ТОС;
- генерацию карточек ТОС;
- генерацию новостей, проектов, потребностей и историй результата;
- генерацию sitemap и индекса страниц;
- аудит внутренних ссылок и базового SEO;
- автокоммит сгенерированных файлов.

Если после запуска нет нового коммита `Generate SEO pages, sitemap and audit`, возможны два варианта:

- workflow прошёл успешно, но не нашёл изменений для коммита;
- workflow не запустился или завершился ошибкой.

В этом случае нужно открыть вкладку `Actions`, найти последний запуск `Generate TOS pages` и проверить лог ошибки. Если workflow не запускался после push, запустить его вручную по инструкции выше.

## 11. Что проверять после обновления

После изменений открыть:

- главную страницу;
- `/tos/`;
- страницу конкретного ТОС;
- `/news/`;
- `/projects/`;
- `/materials/`;
- `/calendar/`;
- `/needs/`;
- `/search/`;
- `/contacts/`.

Проверить:

- меню;
- мобильную версию;
- фильтры каталога;
- привязку материалов к ТОСам;
- отсутствие битых ссылок;
- корректность телефонов и контактов.

Дополнительно после пересборки карточек ТОС проверить любую карточку высокого приоритета, например `/tos/ivanovka/`:

- есть блок статуса сведений;
- кнопка уточнения карточки ведёт на `/update-tos/?tos=ivanovka&type=card#message-builder`;
- кнопка проекта ведёт на `/update-tos/?tos=ivanovka&type=project#message-builder`;
- кнопка потребности ведёт на `/update-tos/?tos=ivanovka&type=need#message-builder`;
- кнопка фотоотчёта ведёт на `/update-tos/?tos=ivanovka&type=photo#message-builder`;
- старых ссылок вида `/update-tos/#template-*` в готовом HTML больше нет.

До полной пересборки старые HTML-карточки защищены `assets/js/site.js`: скрипт исправляет старые ссылки на стороне браузера и добавляет блок статуса сведений из `data/tos_content_audit.json`.

## 13. Что нельзя добавлять в публичные данные

Нельзя публиковать:

- паспортные данные;
- личные переписки;
- закрытые документы;
- пароли, токены, ключи API;
- персональные данные без необходимости;
- спорные обвинения без проверки;
- фотографии детей без осторожного подхода и необходимых согласий.

Для сайта лучше подходят проверенные факты, короткие описания, фотографии результата и понятные контакты для уточнения.
